# How Agents Find Their Workflow

This document explains how an agent, starting from a short trigger prompt, finds everything it needs to execute its task.

---

## The Two-Layer Structure

Every phase session reads two kinds of files that together define behavior:

| File | Location | Contains |
|---|---|---|
| Persona | `.crucible/personas/{specialist}.md` | Who the actor is, principles, mandates, golden rules |
| Activity SOP | `.crucible/sops/{phase}.md` | Step-by-step workflow, handoff protocol, and phase routing |

The **session prompt** generated by `factory.ps1` from `{{crucible_root}}/prompts/{phase}_prompt.md` is the entry point. It tells the agent to read the persona for actor identity and the activity SOP for workflow/routing before doing anything.

---

## Discovery Flow

**Human runs:**
```
agent "Groomer: Next item"
```

**What happens:**

1. `factory.ps1` generates the session prompt from `grooming_prompt.md` and injects it into the agent.
2. Agent reads the prompt and is told to read `personas/groomer.md` for identity and `sops/grooming.md` for workflow/routing.
3. Agent reads `sops/grooming.md` and finds the pass workflow, handoff schema, and quality bar.
4. Agent executes.

No ambiguity. The workflow and routing rules are always in the activity SOP and factory phase policy. The persona defines the actor identity.

## Researcher Task Types

The Researcher has multiple task types, each with its own SOP:

| Trigger | SOP |
|---|---|
| `Researcher: Investigate [TOPIC]` | `{{crucible_root}}/sops/research-investigate.md` |
| `Researcher: Audit [project name]` | `{{crucible_root}}/sops/research-audit-project.md` |
| `Researcher: Audit Crucible` | `{{crucible_root}}/sops/research-audit-framework.md` |

The research activity SOP (`.crucible/sops/research.md`) owns task-type dispatch and phase routing. The Researcher persona stays focused on identity, trust boundaries, and research judgment.

## Adding New Prompts

When adding a new task type for a phase:

1. Create `.crucible/sops/{phase}-{tasktype}.md` with the specialized workflow.
2. Add a row to the dispatch table in the relevant activity SOP.
3. Add the trigger phrase to `{{crucible_root}}/prompts/README.md`.
4. If `factory.ps1` needs to generate the session prompt, update the prompt template.

If it is a new phase with a new actor persona:

1. Create `.crucible/personas/{specialist}.md` for identity.
2. Create `.crucible/sops/{phase}.md` for workflow and routing.
3. Create `{{crucible_root}}/prompts/{phase}_prompt.md` for the session trigger.
4. Register it in `{{crucible_root}}/prompts/README.md`.
5. Update the Context Access Rules table in `OPERATING_MANUAL.md`.
