# How Agents Find Their Workflow

This document explains how an agent — starting from a short trigger prompt — finds everything it needs to execute its task.

---

## The Two-Layer Structure

Every specialist has two files that together define their behavior:

| File | Location | Contains |
|---|---|---|
| Persona | `.crucible/personas/{specialist}.md` | Who they are, principles, mandates, golden rules |
| SOP | `.crucible/sops/{specialist}.md` | Step-by-step workflow for their task type |

The **session prompt** (generated by `factory.ps1` from `{{crucible_root}}/prompts/{specialist}_prompt.md`) is the entry point. It tells the agent to read both files before doing anything.

---

## Discovery Flow

**Human runs:**
```
agent "Groomer: Next item"
```

**What happens:**

1. `factory.ps1` generates the session prompt from `groomer_prompt.md` and injects it into the agent
2. Agent reads the prompt → told to read `personas/groomer.md` (who) and `sops/groomer.md` (how)
3. Agent reads `sops/groomer.md` → finds the 4-pass workflow, handoff schema, quality bar
4. Agent executes

No ambiguity. The workflow is always in the SOP. The prompt is just the trigger.

## Researcher Task Types

The Researcher has multiple task types, each with its own SOP:

| Trigger | SOP |
|---|---|
| `Researcher: Investigate [TOPIC]` | `.crucible/sops/researcher-investigate.md` |
| `Researcher: Audit [project name]` | `{{crucible_root}}/sops/researcher-audit-project.md` |
| `Researcher: Audit Dev Factory` | `.crucible/sops/researcher-audit-factory.md` |

The Researcher persona file (`.crucible/personas/researcher.md`) contains a dispatch table that maps trigger phrases to SOPs.

## Adding New Prompts

When adding a new task type for a specialist:

1. Create `.crucible/sops/{specialist}-{tasktype}.md` with the workflow
2. Add a row to the dispatch table in `.crucible/personas/{specialist}.md`
3. Add the trigger phrase to `{{crucible_root}}/prompts/README.md`
4. If factory.ps1 needs to generate the session prompt: update the prompt template

If it's a new task type for a *new* specialist:
1. Create `.crucible/personas/{specialist}.md` (identity)
2. Create `.crucible/sops/{specialist}.md` (workflow)
3. Create `{{crucible_root}}/prompts/{specialist}_prompt.md` (session trigger)
4. Register in `{{crucible_root}}/prompts/README.md`
5. Update the Context Access Rules table in `OPERATING_MANUAL.md`
